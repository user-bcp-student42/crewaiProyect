# Informe de Security

## 1. Resumen
Revisé la spec y el código entregado, centrándome en autorización, datos personales, credenciales, entradas y configuración de despliegue. Hay riesgos de producción importantes: los identificadores permiten acceder a registros sin sesión, el reinicio de demo está habilitado por defecto y el OTP no tiene límites de intentos. La revisión es estática; no ejecuté pruebas.

## 4. Límites de esta revisión

- No ejecuté pruebas ni verifiqué respuestas HTTP reales. RS-5 requiere comprobar errores del framework y fallos inesperados en ejecución.
- La clave se envía en el cuerpo JSON del paso (`frontend/app.js:24-29`, `220-227`), pero el material no permite comprobar TLS, terminación HTTPS ni configuración de proxy.
- En la respuesta del onboarding, los nombres se devuelven completos, el DNI y celular enmascarados, y no se devuelve la fecha de nacimiento ni la clave (`app/onboarding.py:264-285`). El endpoint de pagos devuelve el nombre del titular (`app/onboarding.py:143-152`). La clave persistida es el hash; no hay código de verificación de clave para pagos en el material entregado.
- No se observan llamadas explícitas de logging de la aplicación con datos personales en los archivos revisados. No se entregó configuración de logs de Uvicorn, proxy, plataforma ni respaldos.
- No hay una ruta de carga de archivos en el material entregado. El almacén usa `json.load` sobre un archivo local (`app/store.py:45-52`); no se ve entrada del cliente que controle esa ruta.
- El contenedor usa el usuario `appuser` (`Dockerfile:12-13`) y las dependencias directas están fijadas (`requirements.txt:1-2`). No se entregaron lockfile, hashes de dependencias transitivas ni resultados de análisis de vulnerabilidades.
- No se ve configuración CORS en la aplicación. La configuración de cabeceras, CORS y TLS de un eventual proxy o plataforma no fue entregada; por tanto, no puedo verificar el despliegue completo.
